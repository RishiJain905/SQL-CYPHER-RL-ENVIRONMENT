What is different in this run

Run 2 lets the model look before it answers. It may run up to 3 queries on a question, sees each result, and its last query is its answer. It starts from run 1b's step 30.

The first test showed a problem. With turns, the untrained model scored 4 points lower on the evaluation set (52.4% to 48.1%). The cause: when a right query returns nothing (no rows, NULL or zero), the model takes that for a mistake and rewrites it.

Option C, the setup this run uses, changes three things:

  1. Turns only where a look can help. gretel and CypherBench have turns. SQaLe and text2cypher keep one query, as in run 1b: their look-around data mostly shows nothing.
  2. Questions whose right answer is nothing are back in training. The question pool had dropped them, so the model never practised them. Now 3 of every 10 gretel questions are of this kind ("returned questions").
  3. A stricter score for them. On an empty database any query returns nothing, so the usual check would pay for anything. These answers must also match on filled copies of the same tables.

Before training, with this setup: 52.4% on the first query and 52.4% after the turns. Where a look can inform, turns fixed 7 answers and broke none. Where the right result is nothing, they broke 7 of 10 right answers. On 50 held-back returned questions the model has 25 right first and 11 after its turns.

What to watch: the share of right answers broken on returned questions should fall, while the other gretel questions are still fixed.
